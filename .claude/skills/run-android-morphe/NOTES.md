# Local development contracts

Paths are repository-relative unless marked workspace-relative. Keep the driver and its sibling source/templates together. Run Python with `-I -B` from trusted code, not from input/extraction directories. Examples are templates, not claims of execution; use independently reviewed identities and NEW external outputs.

## Stage interfaces

| Driver operation | Explicit inputs | Result / limit |
| --- | --- | --- |
| `lab-init` | Archive, `--expect-sha256`, `--desired-change`, `--out` | Untrusted inventory plus separate empty source/tests/stages; identity remains unset |
| `verify-apks` | Exact selected APKs, verification flags, NEW JSON `--out` | Exact supplied set verified, not arbitrary split completeness |
| `preflight` | `--tools FILE`, NEW directory `--out` | Tool probes/pins/SDK36 identity, not patch-build/runtime proof |
| `discover` | APK/hash, Java/JADX paths and hash, literal search, NEW output | Bounded navigation only; original DEX remains authoritative |
| `dex` | Original APK, full selector, Java, exact classpath, NEW output | Require exactly one target across all DEX |
| `patch-build` | `--config FILE` | JVM17 runner/development/test JARs and executed supplied tests, not Android MPP |
| `apply` | `--config FILE` | Actual loader/patch/assertions and emitted DEX; not installable |
| `assemble` | Original APK(s), reviewed apply report, tool/identity/signing flags | Repacked/aligned/signed and verified APK(s), not runtime proof |

Verification flags are `--aapt2`, `--java`, `--signer-jar`, `--expect-package`, `--expect-version-code`, `--expect-version-name`, repeated `--expect-signer`, `--abi`, `--density`, repeated `--language`. Identity pins must be independent of the input's own claims. Standalone non-native ABI is `none`; use `nodpi`/language `none` only if independently established. The verifier uses authoritative aapt2 XML-tree declarations, checks selected topology and declared required ABI/density split types, and records declared/effective minSDK. Proven absent companion versionName may inherit the pinned base value; explicit empty/conflicting values fail. This is not universal resource/language completeness.

## Explicit installed tools

`lab.py` tools JSON: `schema: 1`, with `{path, sha256}` records for `java`, `javac`, `jar`, `aapt2`, `zipalign`, `apksigner_jar`, `d8_jar`, `android_jar`, `jadx_jar`, plus nonempty `dex_classpath`. Full preflight also needs `build_tools_properties`, `platform_properties`, `compiler_classpath`, `runtime_classpath`. Paths are absolute regular files and lists bounded/wildcard-free. `templates/cache-closure.json` pins separate Kotlin2.4.21/Morphe2.3.0 compiler/runtime closures; resolve exactly one matching artifact per coordinate, not every cached JAR.

Discovery defaults are 120 seconds, 1024MiB heap, 20,000 files and 256MiB generated bytes; caps are 300 seconds/2048MiB, with lower byte/file budgets allowed. Literal matches cap at 1,000. Use headless `jadx.cli.JadxCLI`, config disabled, fresh tool-state, no resources, one thread. `java -jar` may launch a GUI and is not this recipe. Child JVM environments strip injected options.

### Read-only APK inventory boundary

`_apk_inventory` admits only ordinary non-directory leaf collision families with distinct exact names matching case-sensitive ASCII `res/[A-Za-z0-9_]+\.xml`, identical literal `res` parent and basenames differing only by ASCII letter case. Each exact `ZipInfo` is read without extraction and retains spelling/payload hash. Links/special entries, exact duplicates, parent/directory/file conflicts, Unicode aliases, nested/extension variants and other families fail. ZIP budgets, metadata/local-header/overlap/compression/encryption validation and full CRC reads remain required.

There is no package exemption or CLI general case-sensitive mode. Extraction, outer APKM, assembly, development packaging and tool-JAR checks retain strict filesystem-safe policies. Accepting read-only inventory does not grant identity/signature/runtime trust or resource/native-edit support.

## Android collection build

`driver.py build --source ABS_REPO --image INSTALLED_IMAGE --out NEW_EXTERNAL_DIR` uses Docker `--pull never`. Source is read-only; a scoped Gradle volume and external output are mounted. Default volume is fresh; `--gradle-volume NAME` explicitly selects an existing approved cache. A private copy omits `.git`, `.gradle`, `build`, `local.properties`; logs, partial outputs, `source.tar`, `work` and `build.json` stay external. Never run host Gradle in the publication checkout.

Tasks must be optional clean, then test, then buildAndroid exactly once; accepted aliases are `clean`, `test`, `buildAndroid` and their `:patches:` forms. No arbitrary properties/init scripts. Optional typed `--publication-repository OWNER/REPO` changes About metadata only; `--version SEMVER` sets version. `--offline` disables container networking and passes Gradle offline for both invocations. Online mode forwards only names of present `GITHUB_TOKEN`, `GITHUB_ACTOR`, `GITHUB_REPOSITORY`; do not retrieve/print credential values. Dependency access is separate from publication.

Default tasks are `:patches:test :patches:buildAndroid`, with rerun/no-build-cache. Exactly one nonempty MPP is required. Detached `:patches:generatePatchesList` consumes that exact MPP without compilation/build dependencies; its hash must stay unchanged. `build.json` records actual MPP/catalog hashes/version and JUnit XML totals. Missing/ambiguous artifacts, version mismatch, missing XML, failed/zero executed tests or validation failures remain failed outputs.

An earlier installed image was `sha256:4b1a74fbffbe6b4e7b6f0171a472478282fb463790a51edf10e465d578f22b69` (`eclipse-temurin:21.0.13_9-jdk-jammy`). Verify current local presence before using it; do not pull implicitly. Workspace standing build approval is scoped, supplies no credentials/download/publication permission and never overrides a new tool denial.

CI offline verification uses no credentials, including fork PRs. Optional collection build runs only target-repository main push/manual events with read-only contents/packages, when `MORPHE_PACKAGES_READ_READY=true`. Actual cross-repository package access must be configured separately; no protected reviewer/environment is required. No `pull_request_target`, credential-bearing PR build or automatic publication.

## App-specific authoring and apply

`templates/patchdev.schema.json` holds command-specific `$defs`, not one combined config. `patch-build` requires `trusted_code`, explicit `jdk`, `cache_root`, NEW `out`, trusted `sources`, `tests`, `assertion_class`, `test_class`. Source/test directories remain separate from untrusted inputs/decompilation. The pinned compiler targets JVM17; runner compiles first, source/assertion second, tests third, then test entrypoint executes. `build.json` retains bundle/runner/assertion/source/tool pins needed for later local handoff.

Adapt fixture examples, not their selectors/identity assumptions. Require exact compatible identity, exactly-one original target, expected registers/operands/branches/exceptions, and rejection of missing/ambiguous/already-patched inputs. The static public assertion signature is `void verify(Map, Map)`; require unchanged keys and every unrelated method identical, bound all allowed deltas and reject no-op. Never use an empty verifier. Synthetic tests must cover wrong operands/control flow, ambiguity, unrelated edits and repeat application.

Apply config fields: `trusted_code: true`, explicit `jdk`, `cache_root`, NEW `out`, `patcher_version: "2.3.0"`; singleton `apks: [{path, sha256}]`; exact `bundle`/`runner` path+hash from build; `assertion_class`, `assertion_sha256`, complete `source_hashes`; unique explicit `patches`, `options: {}`; `verification` with original identity/tool pins above except Java comes from `jdk` (no nested `java`).

Apply freshly verifies inputs, invokes actual Morphe loader, rejects dependencies/options/non-bytecode/incompatible definitions, uses `STRIP_SAFE`, checks patch results, emits/rereads DEX and calls the assertion. Complete method snapshots include metadata/parameters/registers/try/debug and normalized semantic instructions. Class metadata/fields and method-set equality are enforced. Real resource edits remain unsupported; empty resource containers are accepted only with no resource APK/deletion/files. Review `apply.json` and changed methods, not just a DEX header.

## Assembly

Pass `--apk`, `--apply-report`, independent `--expect-apply-sha256`, `--reviewed-apply`, NEW `--out`, original verification flags, explicit `--zipalign`, separately authorized `--keystore`, `--key-alias`, `--ks-pass-env`, final signer pin; optional `--key-pass-env`. Only password environment variable names belong on argv/configs. The general assembler does not create keys. No existing/production key use without authorization.

Default original/emitted DEX name sets must match. Explicit `--allow-dex-layout-change` permits complete contiguous canonical redistribution starting classes.dex without gaps, not partial merging. Preserve all non-signature/non-DEX payloads/compression, remove stale signatures, align and sign v2-only. Scope is API24+; owned installation checks minSDK against live SDK but does not infer app/native behavior. Reinspect exact final methods.

### Bounded APKM base/config support

Explicit `input_mode: "base_config_set"` adds `logical_container: {type: "APKM", path, sha256}`, 2–256 ordered `apks` with exact `archive_member` hashes, and explicit manifest-identified non-native code `base`. Duplicate identities/path aliases fail; filenames do not identify the base. Patches must declare APKM/APKM_REQUIRED; APK-only/null fail before execution. `allow_dex_layout_change` defaults false. Stage/verify the whole set; schema2 apply binds topology/container/member/base mappings and selected local handoff pins.

Split assembly adds `--input-mode base_config_set` plus every `--apk` in exact order. Replace complete base DEX only; companions must be DEX-free. Repack/align/sign every member with one final signer; preserve payload/compression and affirmative v2 evidence. Stored native offsets require16-KiB alignment, not a claim of ELF/runtime compatibility. Outputs are `members/000/{unsigned,aligned,signed}.apk`, then001 etc. Layout change needs apply and assembly opt-in. Feature/code-bearing companions, native bases, native/resource edits, merging, arbitrary containers, rotation and universal resource completeness remain unsupported.

`split_smoke.py build|assemble` uses explicit installed JDK/SDK/NDK r27d/cache, trusted fixture code and NEW external output; assembly requires separately authorized new fixture-only signing. `devices` is separate and consumes the reviewed pinned smoke result. The self-authored resource/JNI fixture passed separate baseline/patched runs for x86_64/arm64-v8a on installed Android30 x86_64/native bridge; that proves only that fixture/image combination, not a vendor app or general ARM support.

## Devices and local checks

`driver.py emulator --sdk ABS_SDK --run NEW_OR_VERIFIED_OWNED_DIR OPERATION`: create/start/install/launch/dump/tap/key/screenshot/logcat/stop. Device operations require applicable explicit standing scope or fresh authorization. A previous success or ownership file alone is not permission. Exact owned process, AVD, serial/private ADB server and ports must match. Install freshly verifies exact APK set/final signer/ABI/minSDK and rechecks bytes immediately before action. Stop requires process exit and both ports released. No global cleanup/PID-kill fallback; deletion needs verified exact owned paths and confirmed shutdown. Emulator04 cleanup remains denied.

`smoke.py` builds the self-authored standalone fixture with explicit installed JDK/SDK/cache/JADX and NEW output, separately authorized `--allow-fixture-key`; optional `--devices` uses two NEW owned baseline/patched runs. Password context ends before device operations. Inspect actual screenshot pixels alongside hierarchy/logs; don't infer runtime success from install acceptance or rewrite machine pending-review fields.
