### Read-only APK inventory boundary

`_apk_inventory` (including fresh `verify-apks` and split-fixture inventory callers) has an internal typed ZIP policy admitting only ordinary non-directory leaf-file collision families whose distinct exact names fully match the case-sensitive ASCII pattern `res/[A-Za-z0-9_]+\.xml`, with the identical literal `res` parent and basenames differing only in ASCII letter case. It reads each exact `ZipInfo` without extraction and retains each spelling and payload SHA-256. Unspecified Unix file type remains permitted; links/special entries remain forbidden. Exact duplicates, parent/directory/file conflicts, Unicode aliases, nested paths, extension variants and all other collision families still fail. Metadata/local-header/overlap checks, compression/encryption restrictions, budgets and full-read CRC checks remain mandatory; inventory is not identity/signature verification or runtime proof.

There is no CLI opt-in, package/hash exemption, retry or general case-sensitive mode. `_validated_zip` defaults to strict filesystem-safe validation; extraction, direct `inspect` of an APK (which first extracts it), outer APKM extraction, patch-development packaging, assembly and tool-JAR checks keep their existing strict policies. An outer APKM may contain eligible aliases *inside* a nested APK because that APK is inventoried without extracting its members; outer-member aliases still fail. Read-only acceptance does not add patch/resource/native assembly support. Device installation still requires fresh whole-APK identity/signature verification and the existing staged-byte guards; no installation/import/runtime result is claimed by this boundary change.
