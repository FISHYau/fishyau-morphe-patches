# Android patch development

Use this directory's `driver.py` from the publication repository root (`repo/` in the parent workspace). Keep `InspectDex.java`, `GenericPatchRunner.kt`, Python siblings, `fixture/` and `templates/` colocated. This is a general app-specific development workflow, **not an automatic semantic patch generator**. Decompiled text cannot supply a correct patch or trusted identity.

## Start here

Read `docs/verification.md` for bounded test status and this directory's `NOTES.md` for configuration/API details. These local entry points do not operate devices or provision tools:

```powershell
py -I -B .claude/skills/run-android-morphe/driver.py --help
py -I -B .claude/skills/run-android-morphe/smoke.py --help
py -I -B .claude/skills/run-android-morphe/test_all.py
```

Before a new task, obtain the exact desired change and observable baseline/patched behavior, authorized input APK/APKM and SHA-256, independently reviewed package/version-code/version-name/certificate pins, explicit installed tool paths, and NEW external lab/output paths. Signing requires separate authorization. Device operations require either explicit standing authorization in applicable user/workspace instructions covering the requested operations, or fresh explicit user approval. A prior successful run or task-specific approval is not standing authorization. Do not operate on preexisting/unowned devices or data, or retry explicitly denied cleanup. Downloads, licenses, keys, Git operations and publication remain separately authorized.

Run Python with `-I -B` from trusted code, never from an archive/decompiler directory. Give each untrusted input/extraction a separate new directory; keep authored executable source and tools separate. All APKs, DEX, caches, keys, build outputs and private UI evidence stay outside the publication repository. Failed/partial outputs are not success and must not be reused as NEW outputs. Pins, `trusted_code` and `--reviewed-apply` are neither authentication, a sandbox nor approval: sources/assertions/tests execute trusted reviewed code.

- The retired `tools/release/`, `tools/manager-check/`, `.github/workflows/release.yml`, `MeasuredJUnit.java` wrapper and their protocol-only tests have been removed. Do not recreate that pipeline. Tool denials still apply and must not be bypassed.

## Driver-first development loop

All names below are `driver.py` subcommands; use explicit absolute input/tool paths and NEW external stage outputs. `patch-build` and `apply` take `--config FILE`; their field contracts are in `templates/patchdev.schema.json` (`$defs` per operation), with the exact dependency closure in `templates/cache-closure.json`. Preflight uses its separate tools-manifest contract in `lab.py`; assembly uses explicit CLI flags in `assembly.py`. See NOTES for examples and handoff fields.

1. **Intake:** `lab-init` takes the archive, `--expect-sha256`, `--desired-change` and `--out`. It copies/inventories untrusted bytes and creates separate source/tests/stages directories. `inspect` supports APKM inventory/extraction; select exact APK paths yourself. Inventory, APKM metadata and generated `lab.json` are not verification or patch source.
2. **Identity and prerequisites:** `verify-apks` takes only the selected APK(s), trusted `--aapt2`, `--java`, `--signer-jar`, independently pinned `--expect-package`, `--expect-version-code`, `--expect-version-name`, repeated `--expect-signer`, and explicit `--abi`, `--density`, repeated `--language`; `--out` is a NEW JSON file. It does not infer missing feature/resource splits or density/language completeness. `preflight --tools FILE --out NEW_DIR` checks explicit hash-pinned tools and compiler/runtime lists; presence-only is not execution or build proof. Stop if identity, scope or prerequisites fail.
3. **Bounded discovery:** `discover` takes one selected APK with its SHA-256, explicit `--java`, `--jadx-jar`, `--jadx-sha256`, literal `--search` and NEW `--out`. It runs headless `jadx.cli.JadxCLI` with config disabled and fresh tool-state, not `java -jar` (which can launch/hang the GUI). Decompiled names/strings are navigation only; retain time/heap/file/byte bounds.
4. **Exact DEX:** `dex` takes the original selected APK, full `--selector` such as `Ldev/morphe/fixture/MainActivity;->label()Ljava/lang/String;`, explicit Java and exact dependency `--classpath`, and NEW output text file. Inspect its exactly-one target count, signature, flags, registers, instructions, branches and exception context before authoring. Never infer uniqueness from JADX or a matching string.
5. **Author externally:** write app-specific Kotlin bytecode patch source, a structural assertion class and positive/negative tests in the lab's trusted source/tests directories. Adapt `fixture/FixturePatch.kt`, `FixtureAssertions.kt` and `FixtureTests.kt`, not their package/selector assumptions. Require exact compatible identity, exactly-one selectors and expected original operands/control flow; reject absent/ambiguous/already-patched targets and unrelated changes. Assertions must constrain the entire allowed change, not merely look for a new string.
6. **Offline build:** `patch-build` compiles runner, reviewed sources/assertions and tests with JDK21, pinned Kotlin2.4.21 and Morphe2.3.0 closure, targeting **JVM17**, then executes the supplied test class. No collection plugin, Gradle resolution or downloads are used. Review `build.json`; the output `development.jar` is a JVM development bundle, **not an Android MPP or Manager artifact**.
7. **Actual apply:** `apply` requires the original APK hash, exact bundle/runner/assertion hashes, build source hashes, explicit patch names, empty options, trusted-code acknowledgement and fresh verification settings. It loads the bundle through the actual Morphe2.3.0 loader, executes selected patches, emits DEX, re-reads complete snapshots and invokes app-specific assertions. Review `apply.json` and changed methods; emitted DEX alone is non-installable.
8. **Assemble:** `assemble` requires the original APK, reviewed/pinned apply report, original identity/signers, explicit Java/aapt2/zipalign/apksigner paths, separately authorized keystore/alias and final signer pin. Supply password environment **names only**, never values or key bytes in configs/logs. It replaces DEX, preserves non-signature/non-DEX payloads and compression, removes stale signatures, aligns, signs v2-only and verifies final identity. Strict DEX name-set equality is default; `--allow-dex-layout-change` permits only reviewed complete contiguous canonical DEX replacement. Scope is API24+; verification now records declared/effective minSDK and owned installation checks it against live SDK, but do not infer native/runtime compatibility from it. Re-read the final exact method(s).
9. **Fresh device verification:** only within applicable explicit standing device authorization or after fresh explicit user approval, use `emulator --sdk SDK --run NEW_DIR create --image INSTALLED_IMAGE`, then that owned run's start/install/launch/dump/tap/key/screenshot/logcat/stop operations. Install always freshly verifies the exact APK(s), final signer and device ABI and rechecks bytes before ADB; a previous JSON is no bypass. Drive the intended feature, inspect actual screenshot pixels as well as hierarchy/logcat, and record baseline versus patched evidence. Separate NEW baseline/patched runs avoid app-data or signer carryover. Stop is confirmed only after process exit **and both owned ports released**; no global cleanup/PID-kill fallback or retry of denied cleanup. Delete an owned disposable AVD/data only when that cleanup is explicitly authorized, ownership and exact paths are verified, and shutdown is confirmed; otherwise stop and ask. This authorization rule does not imply that the driver implements a delete operation.

**Runtime-proven apply/assembly:** one standalone non-native code-bearing APK, independent option-free bytecode patches, unchanged class/field/method sets. Options, dependencies and real resource/native edits remain rejected. An empty resource container is allowed only with no actual resource edits.

**Bounded fixture-backed split support:** explicit `input_mode: "base_config_set"` adds one non-native code base plus DEX-free, base-targeting configuration/resource/native companions. Apply requires a pinned logical APKM, exact selected archive-member hashes and an explicit verified base; patches must declare APKM/APKM_REQUIRED compatibility. Assembly requires `--input-mode base_config_set`, the entire ordered original set and reviewed schema-2 apply evidence; it preserves all companion payloads/compression and aligns/re-signs every output with one final signer. The real self-authored resource/JNI fixture passed separate owned baseline/patched runs, explicit image inspection and confirmed stops for x86_64 and arm64-v8a on the installed Android30 x86_64 image. ARM64 success proves only that fixture/image/native-bridge combination. Required ABI/density type coverage is not universal resource/language completeness. Feature/code-bearing companions, arbitrary containers, split merging, native/resource edits and certificate rotation remain unsupported. See NOTES for exact contracts. This does not verify a vendor app or patch. Out-of-scope apps/changes must stop, not silently broaden the pipeline.

## Real split fixture (bounded runtime proof completed)

`split_smoke.py` is a separate self-authored fixture recipe, not a Spotify converter. `build` takes explicit `--jdk`, `--sdk`, `--ndk` (already installed Windows NDK r27d), `--cache-root`, `--trusted-fixture-code` and NEW external `--out`. `assemble` additionally requires separate fixture signing authorization and `--allow-fixture-key`; the optional `--allow-dex-layout-change` permits only complete canonical redistribution in both apply and assembly. The recipe builds binary resource/config splits and real x86_64/arm64 JNI, checks APKM_REQUIRED positive/APK-only negative compatibility, and assembles the whole set. No download or license acceptance occurs in the recipe.

`devices` is separate: explicit `--jdk`, `--sdk`, a reviewed `--report` plus `--expect-report-sha256`, and NEW external `--out`. It uses separate newly owned baseline/patched runs for each selected ABI, asserts exact label/resource/JNI values, captures private screenshots/logs and confirms stops. `--abi` may bound execution to an assembled variant; ARM translation is not proven unless actual ARM JNI succeeds. Signing passwords leave the process before device operations.

Without `--devices`, it preflights, builds/signs a baseline, discovers/inspects, builds/tests/applies, assembles/verifies and re-inspects DEX without requesting devices. Adding `--devices` requests **two NEW owned AVD runs and their stops**, using already installed `system-images;android-30;google_apis;x86_64`; it launches, taps Show label, asserts BASELINE/PATCHED, captures screenshot/logcat and confirms both stops. Image inspection remains a separate explicit review; do not rewrite the machine record's pending visual-review field. Device operations may rely on applicable explicit standing user/workspace authorization; fixture-key creation and signing still require separate authorization. Neither `--devices` nor `--allow-fixture-key` grants permission.
